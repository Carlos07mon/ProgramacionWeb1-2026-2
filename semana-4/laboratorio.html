/*Experimento 1: La última fila Lo que hice: Comparamos una grilla Flexbox y una Grid con 7 tarjetas. Reducimos el ancho de la ventana. Mis observaciones: Flexbox: En la última fila, las tarjetas sobrantes se estiran para ocupar todo el ancho disponible. Si hay 3 tarjetas en la última fila, cada una ocupa más espacio que las de las filas superiores. Grid: Las tarjetas en la última fila mantienen el mismo ancho que las de las filas completas. Si hay espacio sobrante, este queda vacío a la derecha (o alineado según justify-items), pero las tarjetas no se deforman. Conclusión: Grid mantiene la alineación vertical perfecta entre filas; Flexbox rompe la alineación en la última fila si no se configuran anchos fijos. ¿Cuándo usar Flex aquí? Flex es preferible si el diseño requiere que los elementos "rellenen" todo el ancho disponible (ej. una galería de fotos donde no importa si la última fila es irregular) o si el número de columnas debe ser completamente fluido sin huecos. Experimento 2: El eje que se voltea Lo que hice: Agregué flex-direction: column a un contenedor con justify-content: center y align-items: flex-end. Mis observaciones: Antes (fila por defecto): justify-content: center centraba horizontalmente y align-items: flex-end alineaba abajo. Después (column): justify-content ahora centra verticalmente y align-items ahora alinea a la derecha. Regla descubierta: justify-content siempre actúa sobre el eje principal (la dirección de los ítems) y align-items sobre el eje cruzado (perpendicular). Al cambiar la dirección, las propiedades "parecen" cambiar de función porque los ejes giraron. Experimento 3: La tarjeta que rompe el layout Lo que hice: Inserté una palabra larguísima sin espacios en una celda de Grid. Mis observaciones: Problema: El ancho de la columna se expandió desproporcionadamente para acomodar la palabra, rompiendo el diseño de la grilla. Soluciones probadas: min-width: 0: Funcionó bien, permitió que la celda se encogiera si era necesario. overflow-wrap: break-word: Rompió la palabra en el lugar correcto, manteniendo el ancho de la celda. overflow: hidden: Cortó el texto y añadió puntos suspensivos (si se combina con text-overflow), ocultando el contenido. Mejor resultado: overflow-wrap: break-word es generalmente la solución más segura para textos dinámicos, ya que preserva el contenido. min-width: 0 es útil si quieres que el elemento ceda espacio. Experimento 4: Mover cosas sin tocar el HTML Lo que hice: Cambié la posición de la barra lateral (sidebar) de izquierda a derecha y luego arriba del contenido principal, solo modificando el CSS. Mis observaciones: Con Grid: Usé grid-template-areas o grid-column para reordenar. Cambié el orden visual sin tocar el HTML. El HTML sigue siendo header, aside, main, footer, pero la visualización cambió. Comparación: Con float o position: absolute, habría tenido que cambiar el HTML o añadir clases complejas para lograr el mismo efecto. Conclusión: Grid permite una separación total entre la estructura semántica (HTML) y el diseño visual (CSS), facilitando el mantenimiento y el diseño responsive. Experimento 5: gap vs margin Acción: Comparé dos secciones idénticas: una con margin: 8px en cada tarjeta y otra con gap: 16px en el contenedor. Mis observaciones: Margin: Al usar margin en los ítems, hay un "doble margen" en el espacio exterior (el primer y último ítem empujan el borde del contenedor). Para evitarlo, hay que escribir reglas específicas como :first-child { margin-left: 0 } y :last-child { margin-right: 0 }. Gap: El espacio gap se aplica solo entre los elementos. No afecta los márgenes exteriores del contenedor. El diseño es más limpio y no requiere reglas de excepción. Conclusión: gap es superior para espaciado interno en Flexbox y Grid, ya que simplifica el código y evita errores de diseño en los bordes. */
